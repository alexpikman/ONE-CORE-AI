# ONE CORE AI
## Полный план разработки интеллектуального AI-пространства

**Концепция:** GPT Chat Experience + ONE CORE Intelligence  
**Тип приложения:** локальная AI-платформа с возможностью расширения  
**Основной режим:** персональное рабочее пространство для общения, исследований, разработки и управления AI-агентами.

---

# 1. Концепция и принципы продукта

ONE CORE AI — единое пространство взаимодействия человека с искусственным интеллектом.

Пользователь общается с AI привычным способом, как в ChatGPT, но при этом может подключать различные модели, использовать инструменты, создавать проекты, работать с файлами, запускать задачи и делегировать работу специализированным агентам.

Основные принципы:

1. Простота интерфейса — пользователь не должен разбираться в технической архитектуре.
2. Единое пространство — общение, проекты, файлы, инструменты и настройки доступны из одного приложения.
3. Независимость от поставщика моделей — пользователь сам выбирает AI-провайдера.
4. Локальная работа — приоритет собственным моделям и данным пользователя.
5. Контроль действий — AI не выполняет опасные операции без разрешения.
6. Расширяемость — новые модели, инструменты и агенты подключаются без перестройки приложения.
7. Прозрачность — пользователь видит, что AI делает, какие ресурсы использует и на каком этапе находится.

# 2. Пользовательский интерфейс — основа GPT Chat

Главный экран должен быть построен на привычной модели ChatGPT.

## 2.1. Левая панель навигации

Постоянная боковая панель:

- Логотип ONE CORE.
- Кнопка «Новый чат».
- Поиск по истории.
- История диалогов.
- Закреплённые диалоги.
- Проекты.
- Библиотека файлов.
- AI-агенты.
- Инструменты.
- Настройки.
- Профиль и состояние системы.

История чатов должна работать так же удобно, как в ChatGPT: группировка по времени, переименование, закрепление, удаление, поиск и продолжение диалогов.

## 2.2. Центральная рабочая область

Центр приложения — чат.

Необходимо реализовать:

- Приветственный экран.
- Поле ввода сообщения.
- Отправку по Enter.
- Перенос строки по Shift+Enter.
- Потоковую генерацию ответа.
- Markdown.
- Подсветку программного кода.
- Копирование кода.
- Копирование ответа.
- Повторную генерацию.
- Редактирование пользовательского сообщения.
- Продолжение ответа.
- Остановку генерации.
- Вложения.
- Изображения.
- Документы.
- Контекст текущего проекта.
- Выбор модели.
- Отображение статуса модели.
- Голосовой ввод и вывод.

Сообщения должны иметь единый аккуратный визуальный стиль. Не нужно превращать каждый ответ в отдельную карточку с большим количеством рамок.

## 2.3. Панель ввода

Поле сообщения — один из важнейших элементов интерфейса.

Внутри или рядом с ним:

- Текстовый ввод.
- Прикрепление файлов.
- Добавление изображений.
- Голосовой ввод.
- Выбор модели.
- Выбор режима работы.
- Отправка.
- Остановка генерации.

Под полем можно показывать активный проект и подключённые источники контекста.

## 2.4. Верхняя панель чата

- Название диалога.
- Текущая модель.
- Индикатор подключения.
- Выбор режима работы.
- Доступ к информации о контексте.
- Дополнительные действия с диалогом.

# 3. Собственная обложка ONE CORE

Главное отличие от ChatGPT — собственная визуальная идентичность.

Не копировать внешний вид бренда ChatGPT. Использовать его UX-подходы, но разработать собственный интерфейс.

## 3.1. Стартовый экран

При первом открытии пользователь видит полноценную обложку ONE CORE.

Состав:

- Центральный фирменный знак.
- Название ONE CORE.
- Короткое описание возможностей.
- Поле начала общения.
- Несколько примеров задач.
- Индикатор состояния системы.
- Информация о подключённой модели.

После начала общения стартовая обложка естественно переходит в обычный чат.

## 3.2. Визуальный язык

Направление дизайна:

- Светлый интерфейс.
- Arctic / Soft Glass.
- Белые и светло-голубые поверхности.
- Мягкие синие и голубые акценты.
- Скруглённые формы.
- Тонкие границы.
- Полупрозрачные элементы.
- Минималистичные SVG-иконки.
- Плавные переходы и анимации.
- Единая типографика.

Не использовать тяжёлые тёмные панели, перегруженные градиенты, чрезмерные тени и декоративные элементы без функционального назначения.

## 3.3. Адаптивность

Интерфейс должен корректно работать:

- На широких мониторах.
- На ноутбуках.
- На планшетах.
- На мобильных устройствах.

Боковая панель на мобильных устройствах превращается в выдвижную навигацию.

# 4. Чат и управление диалогами

Это фундамент приложения. Сначала необходимо добиться полноценной работы чата, а уже затем расширять систему агентами.

Функциональные пункты:

1. Создание нового диалога.
2. Автоматическое название диалога.
3. Сохранение истории.
4. Продолжение старых диалогов.
5. Поиск по истории.
6. Переименование.
7. Закрепление.
8. Архивирование.
9. Удаление с подтверждением.
10. Экспорт диалога.
11. Импорт диалога.
12. Копирование сообщений.
13. Редактирование сообщений.
14. Повторная генерация.
15. Отмена генерации.
16. Потоковая выдача ответа.
17. Восстановление состояния после перезапуска.
18. Обработка ошибок соединения.
19. Отображение времени и статусов.
20. Работа с длинными диалогами и контекстом.

Важно: сообщения, история, настройки и состояние генерации должны быть независимыми сущностями, а не храниться внутри одного большого объекта интерфейса.

# 5. Система AI-провайдеров

ONE CORE не должен зависеть от одной нейросети.

Создать единый Provider Engine — слой взаимодействия с моделями.

Поддерживаемые подключения:

- Ollama.
- LM Studio.
- OpenAI-compatible API.
- OpenAI.
- Anthropic.
- Другие совместимые провайдеры.

Для каждого провайдера:

- Адрес подключения.
- Авторизация.
- Проверка соединения.
- Получение списка моделей.
- Выбор модели.
- Загрузка модели, если поддерживается.
- Выгрузка модели, если поддерживается.
- Температура.
- Максимальный контекст.
- Системная инструкция.
- Таймауты.
- Обработка ошибок.
- Отображение доступности.

У каждого провайдера должен быть единый интерфейс, чтобы добавление новой интеграции не требовало переписывать чат.

# 6. Управление моделями

Создать отдельный Model Manager.

Функции:

- Список доступных моделей.
- Информация о модели.
- Размер модели.
- Контекстное окно.
- Статус загрузки.
- Статус активности.
- Загрузка и выгрузка.
- Удаление локальных моделей.
- Проверка доступной памяти.
- Выбор модели по умолчанию.
- Сопоставление модели с задачей.
- Возможность назначить разные модели разным агентам.

В чате отображать фактически используемую модель, а не просто выбранное пользователем название.

# 7. Agent Engine — интеллектуальная система агентов

Это ключевая особенность ONE CORE.

Пользователь может общаться с одним главным AI, а внутри система распределяет задачи между специализированными агентами.

Основные роли:

**MANAGER**
- Принимает запрос пользователя.
- Определяет цель.
- Разбивает сложную задачу на этапы.
- Назначает исполнителей.
- Контролирует общий процесс.
- Передаёт результат пользователю.

**ANALYST**
- Анализирует задачу.
- Изучает файлы и контекст.
- Определяет требования.
- Выявляет риски.
- Подготавливает техническое задание.

**DEVELOPER**
- Пишет код.
- Изменяет файлы.
- Работает с проектом.
- Выполняет технические задачи.

**REVIEWER**
- Проверяет результат.
- Ищет ошибки.
- Сравнивает результат с требованиями.
- Формирует замечания.

Дополнительные роли должны подключаться через реестр агентов, без изменения основного ядра.

Для каждого агента:

- Название.
- Роль.
- Системная инструкция.
- Назначенная модель.
- Разрешённые инструменты.
- Доступный контекст.
- Статус.
- История работы.
- Лимиты.
- Настройки.

Важно: агент не должен считаться выполнившим задачу только потому, что он сообщил об успехе. Нужна проверка фактического результата.

# 8. Task Engine — управление задачами

Отдельный движок выполнения задач.

Каждая сложная задача должна иметь:

- Уникальный ID.
- Описание.
- Цель.
- План.
- Этапы.
- Исполнителя.
- Статус.
- Результаты.
- Ошибки.
- Историю событий.

Состояния задачи:

- Создана.
- Анализируется.
- Ожидает выполнения.
- Выполняется.
- Ожидает разрешения.
- Проверяется.
- Завершена.
- Ошибка.
- Отменена.

Пользователь должен видеть, что именно происходит.

Например:

1. MANAGER принял задачу.
2. ANALYST изучает требования.
3. DEVELOPER выполняет работу.
4. REVIEWER проверяет результат.
5. MANAGER формирует итоговый ответ.

Для длительных задач необходимы пауза, продолжение, отмена и восстановление после перезапуска.

# 9. Tool Engine — инструменты

Создать единый механизм подключения и вызова инструментов.

Базовые инструменты:

- Чтение файлов.
- Создание файлов.
- Редактирование файлов.
- Удаление файлов.
- Поиск по проекту.
- Выполнение команд.
- Работа с терминалом.
- Git.
- GitHub.
- SSH.
- Веб-браузер.
- Работа с изображениями.
- Работа с документами.
- Получение системной информации.

Каждый инструмент должен иметь:

- Название.
- Описание.
- Схему входных данных.
- Результат.
- Уровень риска.
- Разрешения.
- Журнал вызовов.
- Обработку ошибок.

Опасные действия должны требовать подтверждения пользователя.
